01 / The problem

40+ live orders, 20+ suppliers, and the truth scattered across inboxes.

Nothing was broken, it was just slow. Every question about an order meant searching threads, opening spreadsheets or asking whoever last spoke to the supplier.

Status

Lived in email threads

Whether an order was paid, in production or ready to collect was written somewhere in a thread with the supplier, the forwarder or the client.

Pricing

Lived in spreadsheets

Dozens of supplier price lists in Excel, one of them around 240,000 lines. Pricing a list of codes meant opening files one at a time.

Follow-up

Lived in people's heads

Who owes us a reply, which order needs chasing, which payment is due. Easy to drop when 40 orders are moving at once.

04 / How it's built

Plain parts, wired so a mistake is cheap to spot and undo.

A scheduled Python agent reads the mailbox, a language model turns each email into strict JSON, and a small cloud API applies it to the hub, where every change is logged.

1 · Source

Outlook mailbox

Inbox and sent mail through Microsoft Graph. Read and draft permissions only, no send.

2 · Agent

Python mail agent

Runs every 15 minutes. Reads attachments, loads open projects, known orders and past lessons.

3 · Model

Language model

Returns one strict JSON object per email: type, project, supplier, stage, dates, lead time, reply draft.

4 · Hub

Cloud API + database

Validates the result, updates cards and requests, and writes an audit entry with the source email.

Team web app

Today, requests, projects, shipments, prices, stock.

Outlook drafts

Replies created in the thread on a button press, never sent.

Quote extension

Exact-match costs into the quoting tool.

Xero

Sales invoices created as drafts only.

Feedback loop: every Right, Fix it, Wrong or undo is saved as a lesson. The agent reads those lessons first on its next run, so a mistake I correct once doesn't come back.

  • Nothing missed, nothing counted twice. Each run re-scans a 6-hour overlap and skips messages it has already processed.
  • Sent mail reads differently. What we send is our own confirmed action. What a supplier sends is a claim until it says otherwise.
  • Attachments count as evidence. Proformas, packing lists and POs are read, and the order reference is taken from the file when the body doesn't have it.
  • Failures don't block the queue. Busy or rate-limited calls retry with backoff. An email that fails 3 times is set aside for a person.
  • Built to run on free tiers. The 240k-code catalogue is split into sorted chunks with a binary-search index, so each lookup stays within the free plan's limits.
  • Tested before it ships. Automated test suites cover the hub's API, permissions and screens, and the invoice builder.

05 / Rules it can't break

Useful only if the team can trust it, so the limits come first.

Most of the design work went into what the agent is not allowed to do.

It can't send email

No send permission. Replies, follow-ups, purchase lists and invoices are drafts until a person confirms.

It never invents a number

Missing prices, dates and lead times stay blank. A guess is worse than a gap.

Exact codes only

A near-match product code is shown for review. It is never filled in automatically.

Money stays private

Invoices, proformas and costs are kept out of shared project files and shown to admins only.

Every change is traceable

Each card change is logged with the email it came from, and can be undone from the card or from Today.

Autonomy is earned

An action type runs on its own only after five correct calls in a row, and I can pause it at any time.

06 / My part

  • Designed the data model: projects, supplier orders, requests, price lists, stock, quote snapshots and an audit log.

07 / What I'm measuring next

Proving it with numbers, not impressions.

  • Agent accuracy: share of proposals marked Right, by action type, week over week.
  • Speed to status: time from a supplier email arriving to the order card being correct.
  • Early warnings: late orders flagged for chasing before the client's due date, not after.
  • Quote turnaround: time from a pricing request to a sent quotation.
